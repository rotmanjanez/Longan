# Lychee domain model and database schema (reference for the "Longan" TypeScript port)

Source: `/tmp/lychee-src/Lychee` (Laravel 12 / PHP, Vue 3 front-end, v7.12-ish, 2026-11). Read-only reference.
Everything below was read from `app/Models`, `app/Policies`, `app/SmartAlbums`, `app/Image`, `app/Assets`,
`config/*.php`, `database/migrations` and `docs/specs/4-architecture/{album-tree-structure,tag-system}.md`.
There is NO `database/schema` dump; the "final schema" in section 5 is reconstructed from the model docblocks and the
latest create/alter migrations.

Conventions: `ID24` = `char(24)` random string primary key (`App\Constants\RandomID::ID_LENGTH = 24`, non-incrementing,
generated by the app, not DB). `int` ids are auto-increment. Booleans are `tinyint(1)`.

### 1.3 Smart albums (`app/SmartAlbums`, NOT Eloquent, NOT persisted)
Singleton classes extending `BaseSmartAlbum implements AbstractAlbum`; each supplies a `smart_condition` closure over the `photos` query,
then the standard photo-visibility policy is applied. IDs are strings (`SmartAlbumType` enum), so they live in the same id-space as
album ids for `album_user_thumbs.album_id` and `access_permissions.base_album_id`.
| Id | Condition |
|---|---|
| `unsorted` | no row in `photo_album` (`photo_album.album_id IS NULL` after left join) |
| `highlighted` | `photos.is_highlighted = true` (was `is_starred`; renamed 2026-02) |
| `recent` | `photos.created_at >= now - recent_age days` (config `recent_age`) |
| `on_this_day` | `photos.month_day_key = month*100+day(today)` and (taken_at not null OR uploaded before this year) |
| `untagged` | photo has no tags |
| `unrated` / `one_star`..`five_stars` | `rating_avg IS NULL` / `rating_avg` in [n, n+1) |
| `best_pictures`, `my_best_pictures` | top-rated incl. ties (Supporter-Edition gated); `my_*` uses current user's `photo_ratings` |
| `my_rated_pictures` | photos rated by current user |
| `timeline` | exists as class, ID `timeline`, always `false` in the enabled list; special timeline page (`timeline_page_enabled`, `timeline_photos_public`) |
There is NO "public" smart album. Each smart album's enable flag is a config key (`enable_unsorted`, `enable_recent`, `enable_highlighted`,
`enable_on_this_day`, `enable_untagged`, `enable_unrated`, `enable_1_star`.., `enable_best_pictures`, ...). Related configs:
`SA_override_visibility` (skip security filter), `hide_nsfw_in_smart_albums`, `enable_smart_album_per_owner`, `recent_age`.
A smart album can be made public by an `access_permissions` row whose `base_album_id` is the smart album key (`SetSmartProtectionPolicy`).
Non-admin visibility: `AlbumPolicy::canSee` (needs `may_upload` or a public grant).

## 2. Album tree, inheritance, smart albums

### 2.1 Class-table inheritance (not single-table)
```
users 1---* base_albums <-- 1:1 --+-- albums       (regular; has parent_id,_lft,_rgt)
 (owner_id)                       +-- tag_albums   (tag criteria; no tree)
                                  +-- person_albums(person criteria; no tree)
```
* Common stuff (title, owner, nsfw, sort, perms) is in `base_albums`; the child table PK is also an FK to `base_albums.id` (`id` is identical).
* In PHP `BaseAlbum` is an abstract Eloquent class, `ForwardsToParentImplementation` forwards attribute reads/writes of the shared columns to a
  `BaseAlbumImpl` instance held in `$base_class`; save() writes both rows; delete() removes the base row.
* Photos link to ANY of these via `photo_album(photo_id, album_id)` (pivot, composite PK; has `bucket_key` too). FK `photo_album.album_id -> albums.id`, so only regular albums have physical photos;
  tag/person albums compute their photos dynamically.
* `access_permissions.base_album_id`, `statistics.album_id`, `album_user_thumbs.album_id` reference `base_albums.id` (or smart-album key).

### 2.2 Nested set (kalnoy/nestedset, LycheeOrg fork)
* Columns: `albums.parent_id` (adjacency, FK self), `_lft`, `_rgt` (unsigned bigint), index `(_lft asc, _rgt desc)`.
* Node A is descendant of B iff `A._lft > B._lft AND A._rgt < B._rgt`. Leaf iff `_lft = _rgt - 1`. Ancestors of X: `_lft <= X._lft AND _rgt >= X._rgt`.
* The library maintains `_lft/_rgt` on insert/move/delete (shifts all subsequent rows -> writes are O(N), reads cheap). `fixTree()` rebuilds from `parent_id`.
  Root albums = `parent_id IS NULL`; there is no explicit "root row" (forest of trees).
* Album delete: `deleteDescendants()` is a deliberate no-op; the `Delete` action handles the subtree (photos that are only in deleted albums are deleted).
* Tree-derived denormalised data (must be kept up to date by listeners/jobs): `num_children`, `num_photos`, `min/max_taken_at`, auto-cover ids,
  `album_size_statistics`, `is_recursive_nsfw` (`SyncRecursiveNsfw`), owner propagation to descendants (`Album::fixOwnershipOfChildren`).
* Child ordering = parent's `album_sorting_col/order` (`SortingDecorator`, natural sort via `title_base/title_index`).
* Photo ordering inside album = `base_albums.sorting_col/order` (else config default).

### 2.3 Tag albums & tags (docs/specs/4-architecture/tag-system.md)
* `photos_tags(photo_id, tag_id)` unique pair; `tag_albums_tags(album_id -> tag_albums.id, tag_id)` = the tag criteria; `albums_tags(album_id -> albums.id, tag_id)` = plain labels on regular albums (feature 050).
* Tag album photo query: `EXISTS (select from photos_tags where tag_id IN (...) and photo_id = photos.id group by photo_id having count(distinct tag_id) = N)`.
* Tags are global; rename/merge/delete are per-user-scoped (only the current user's photos/tag-albums are re-pointed) then orphan cleanup.

## 3. Photo and size variants

### 3.1 Size variant types (`App\Enum\SizeVariantType`, stored as int in `size_variants.type`)
| int | name | notes |
|---|---|---|
| 0 | `raw` | raw camera file (e.g. .dng) if photo is a RAW |
| 1 | `original` | the uploaded file as-is |
| 2 | `medium2x` | 2 x medium max dims |
| 3 | `medium` | config `medium_max_width/height` (default 1920 wide) |
| 4 | `small2x` | 2 x small |
| 5 | `small` | config `small_max_width/height` (defaults 0 x 360, i.e. height-bound) |
| 6 | `thumb2x` | 400 px square crop |
| 7 | `thumb` | 200 px square crop (jpeg) |
| 8 | `placeholder` | 16 px webp; stored as base64 inside `short_path` (not a file) |
Generation (`SizeVariantDefaultFactory`): order PLACEHOLDER, THUMB, THUMB2X, SMALL, SMALL2X, MEDIUM, MEDIUM2X. Thumb/placeholder = crop; others = scale to fit.
Skipped when disabled by config (`medium_2x`, `small_2x`, `thumb_2x`, `low_quality_image_placeholder`, max dims 0/0), when the source is too small
(`isLargeEnough`), when it already exists, and (medium/medium2x) for videos. Fallback chain for display: small2x -> small -> thumb; thumb2x -> thumb.
Thumbnail-type variants used for album covers: small, small2x, thumb, thumb2x, placeholder.

### 3.2 Storage layout and naming
* Laravel Flysystem disks (`config/filesystems.php`): `images` (local, root = `public/uploads/` or `LYCHEE_UPLOADS`, public URL) and `s3`. `size_variants.storage_disk` records which.
  Other fs areas: `image-upload`, `image-jobs` (temp), `dist`.
* Path = `{typeName}/{ab}/{cd}/{28 hex chars}{suffix}{ext}` e.g. `original/3f/a9/c0d1...e7.jpg`, `medium/3f/a9/c0d1...e7.jpg`, `thumb/.../...jpeg`.
  (`SizeVariantGroupedWithRandomSuffixNamingStrategy`: 32 random hex chars = `bin2hex(random_bytes(16))` split 2/2/28; ALL variants of one photo share the same random middle path,
  re-derived from the original's path.) Original filename is NOT kept on disk (title is derived from it).
* Extension: original/raw keep the source extension; thumb/thumb2x always `.jpeg`; placeholder `.webp`; other generated variants follow config `size_variant_format`
  (`original`|`jpeg`|`webp`|`jxl`); non-photo (video) previews use `.jpeg`.
* `short_path_watermarked` is a second file for the watermarked render (`WatermarkGroupedWithRandomSuffixNamingStrategy`).
* Live photo companion video: `photos.live_photo_short_path` (+`live_photo_content_id`, `live_photo_checksum`), same disk.
* Public URL = disk url + `/` + short_path (via `UrlGenerator::pathToUrl`; optional symlink/temporary-url layer exists in config but `sym_links` table was dropped).

### 3.3 Photo columns (final)
* identity: `id ID24`, `owner_id`, `created_at`, `updated_at`; `title` (<=300, nullable) + `title_base`, `title_index`, `title_date_key` (natural sort/bucketing); `description` (text).
* file: `type` (mime string e.g. `image/jpeg`, `video/mp4`, <=30), `filesize` (bigint), `checksum` (sha1, 40; of the stored/processed file), `original_checksum` (sha1 of uploaded bytes; duplicate detection),
  `license` (string enum: none, reserved, CC0, CC-BY..., default `none`), `is_validated` (upload moderation), `duration`, `fps` (videos).
* EXIF-ish strings: `make`, `model`, `lens`, `iso`, `aperture`, `shutter`, `focal` (all nullable strings).
* geo: `latitude` decimal(10,8), `longitude` decimal(11,8), `altitude` decimal(10,4), `img_direction` decimal(10,4), `location` (reverse-geocoded text); index `(latitude, longitude)`.
* time: `taken_at` datetime(UTC) + `taken_at_orig_tz` (<=31 chars, tz where taken), `initial_taken_at` + `initial_taken_at_orig_tz` (backup before edits),
  derived keys: `taken_key` (`Y-m-d-H` local), `month_day_key` (month*100+day), `title_date_key`.
* flags/ratings: `is_highlighted` (ex-`is_starred`), `rating_avg` (denormalised avg of photo_ratings; null = unrated).
* 360/pano: `is_360`, `pano_full_width/height`, `pano_crop_left/top`.
* AI: `face_scan_status`, `face_count`, `nsfw_status`, `upload_trust_level`.
* Removed over time: `album_id` (-> pivot `photo_album`), `is_public` (-> album access_permissions), `tags` text (-> `photos_tags`), `star`, `thumb*` columns (-> size_variants), `legacy_id`, `sym_links`.
* A Photo has NO own access flags: visibility is entirely derived from the albums containing it (plus owner). Photos in no album = "unsorted" (owner/admin only).
* Upload pipeline (Pipes under `app/Actions/Photo/Pipes`): find duplicate by checksum -> extract metadata (exiftool/native) -> compute `original_checksum` -> pick naming strategy -> save original ->
  create size variants -> palette/colours -> (optional) faces/nsfw jobs -> attach to album(s) -> update album computed fields.

## 4. Access control

### 4.1 Pieces
* **Owner**: `base_albums.owner_id`. Owner and `users.may_administrate` (admin; `BasePolicy::before` returns true for every ability) bypass everything.
  Child albums normally share the owner of the parent (ownership change is propagated down the subtree).
* **Public flag is not a column.** An album is "public" iff an `access_permissions` row exists for it with `user_id IS NULL AND user_group_id IS NULL`.
* **NSFW**: `base_albums.is_nsfw` (+ denormalised `albums.is_recursive_nsfw`). Sensitive albums are hidden from smart albums/search/listings unless user opted in (config `hide_nsfw_in_smart_albums`, front-end warning overlay).
* **Link-required (hidden)**: `access_permissions.is_link_required = true` -> reachable if you have the URL/id but NOT listed in public listings.
* **Password**: `access_permissions.password` (bcrypt hash, 100) on the public row. Unlocking stores album id in the session key (`AlbumPolicy::UNLOCKED_ALBUMS_SESSION_KEY`); `getUnlockedAlbumIDs()` feeds query filters.
* **Default for new albums**: config `default_album_protection` (enum private / public / inherit / public_hidden), applied by `Album\Create`.

### 4.2 `access_permissions` table
| column | notes |
|---|---|
| `id` bigint | |
| `base_album_id` char24 | album (or smart-album key string) |
| `user_id` uint null FK users (cascade) | grant to a specific user |
| `user_group_id` uint null | grant to a group (any member inherits) |
| `is_link_required` bool=false | public-but-unlisted |
| `password` string(100) null | hash |
| `grants_full_photo_access` | can see `original` variant (otherwise capped at medium) |
| `grants_download` | can download archive/photos |
| `grants_upload` | can upload into album |
| `grants_edit` | can edit album/photos metadata |
| `grants_delete` | can delete |
| `grants_move` | (added 2026-09) can move photos |
| `created_at`, `updated_at` | |
| virtual `user_id_unique_key`, `user_group_id_unique_key` = COALESCE(col,0) | unique `(base_album_id, user_id_unique_key, user_group_id_unique_key)` so exactly one row per (album,user) / (album,group) / (album,public) |
Row kinds: (user NULL, group NULL) = public; (user set) = per-user share; (group set) = per-group share. User-specific rows win over group rows (`getComputedAccessPermissionSubQuery`).
Helpers: `AccessPermission::ofPublic()`, `ofPublicHidden()`, `withGrantFullPermissionsToUser()`; public defaults read configs `grants_full_photo_access`, `grants_download`.

### 4.3 Listing visibility - app/Policies/AlbumQueryPolicy.php (SQL level)
Query is LEFT JOINed to a sub-query `computed_access_permissions` = rows of access_permissions for the current viewer
(guest: `user_id IS NULL AND user_group_id IS NULL`; logged-in: his own `user_id` rows UNION his groups' rows not overridden by a user row; the public row is NOT included for logged in users - they get it through `current_user_permissions()` or `public_permissions()` in PHP).
Four named filters (all return the query unchanged for admins):
1. **Visibility** (`applyVisibilityFilter`): listed in e.g. root listing iff `is_link_required = false` on the computed permission, OR viewer is owner.
2. **Accessibility** (`appendAccessibilityConditions`): permission row exists and password is null, OR password set and album id in unlocked list, OR owner.
3. **Reachability** (`applyReachabilityFilter`): visible AND (no password OR unlocked) OR owner.
4. **Browsability** (`applyBrowsabilityFilter`): album is reachable AND no ancestor between the origin and the album (using `_lft/_rgt` self-join `inner`) is blocked, where blocked = link-required OR no permission OR password-not-unlocked, and not owned by viewer. i.e. a path-wide check along the nested set; permissions are NOT inherited, each ancestor must independently be openable.
Also `appendRecursiveSensitiveAlbumsCondition` (any ancestor is_nsfw) and `PhotoQueryPolicy::applySearchabilityFilter/applySensitivityFilter` for photos (photo is searchable if it is in at least one album reachable by viewer, or owned by viewer).
### 4.4 Per-request policy (PHP side, `AlbumPolicy` / `PhotoPolicy`)
`canAccess` (owner || current_user_permissions != null || public perm with no password or unlocked), `canDownload`, `canUpload`, `canEdit`, `canMove`, `canDelete`, `canAccessFullPhoto`, `canShare*`, `canTransfer`, `canChangeProtectionPolicy` (owner/admin),
`canSee` for smart albums, plus metrics/face/purchase abilities. Photo abilities reduce over the photo's albums (`reduction()`): the photo is visible/editable if ANY containing album allows it.
Users/group management (`UserPolicy`, `UserGroupPolicy`), settings (`SettingsPolicy`: admin only), tags (`TagPolicy`).
### 4.5 Essential vs optional for a port
Essential: owner_id, admin flag, `access_permissions` (user/group/public rows + is_link_required, password, grants_*), is_nsfw, the 3-4 listing predicates, session-unlocked list, per-album grants check, photo-via-albums rule.
Optional: groups (`user_groups`, `users_user_groups`), `grants_move`, `shared_albums_visibility`, recursive-NSFW denormalisation, upload trust level, album_user_thumbs cache.

* 583 migration files in `database/migrations` (2014 -> 2026-11-01, PHP anonymous classes). Roughly 56 `Schema::create` files; the bulk of the rest are config-row inserts (`*_add_*_config.php`, `bump_version*`)
  and data back-fills. Notable history: v3 (int ids, `albums`/`photos` with embedded thumbs) -> 2021-12 `refactor_models` (random 24-char ids, base_albums/albums/tag_albums, size_variants)
  -> 2023-05 `access_permissions` (replaced `is_public/requires_link/password/...` on base_albums, `user_base_album`) -> 2025-05 `photo_album` pivot & `tags`, `user_groups`, `palettes`
  -> 2025-12..2026 ratings, tracks, album statistics, faces/persons, nsfw, orders/webshop, landing, webhooks -> 2026-10/11 bucket keys, 360 photos, `month_day_key`.
* There is NO schema dump; tests run `migrate` on sqlite/mysql/pgsql (`phpunit*.xml`). Supported: MySQL/MariaDB, PostgreSQL, SQLite.
* Timestamps: `created_at/updated_at` datetime(6) UTC; model trait `UTCBasedTimes`.

## 6. Config system

### 6.1 `configs` table (model `Configs`, repo `App\Repositories\ConfigManager`)
* Flat key/value store, ~570 distinct keys inserted by migrations (each feature migration inserts its rows; `BaseConfigMigration` helper classes).
* Columns: `key` (unique), `value` (string, <=200, nullable; everything serialised as text: `'0'|'1'`, ints, strings), `cat` (category, FK-by-convention to `config_categories.cat`: Gallery, Admin, Image Processing, Smart Albums,
  Mod Map/NSFW/Cache/RSS/Search/Pro/Privacy/Frame/Welcome/Timeline/Flow, Footer, Users Management, Social Media, Symbolic Link, lychee SE, ...),
  `type_range` (validation DSL), `is_secret`/`confidentiality`, `description`, `details` (help text), `level` (0 basic / 1 advanced / 2 expert -> UI ordering), `not_on_docker`, `order`, `is_expert`, `required_keys` (dependency on other keys).
* `type_range` values (`ConfigType`): `0|1` (bool), `0|1|2` (ternary), `int`, `positive`, `int:min:max`, `string`, `string_required`, `string_file_size` (`512MB`), `color` (`#rrggbb`), `license`, `map_provider`, `currency`, `password`, `admin_user`,
  or an enum list like `a|b|c` (e.g. `ASC|DESC`, `always|hover|never`, `original|jpeg|webp|jxl`). `Configs::sanity()` validates a candidate value.
* `ConfigManager`: lazy-loads the whole table into an in-process array cache; `getValueAsBool/Int/String/ByteSize/Enum`; `invalidateCache()` on update. Also runtime capability probes: `hasImagick`, `hasJxl`, `hasExiftool`, `hasFFmpeg`.
* Examples relevant to a gallery core: `default_license`, `medium_max_width/height`(1920), `small_max_width/height`, `medium_2x`, `small_2x`, `thumb_2x`, `low_quality_image_placeholder`, `compression_quality`(90),
  `size_variant_format`, `upload_processing_limit`, `grants_full_photo_access`, `grants_download`, `default_album_protection`, `hide_nsfw_in_smart_albums`, `SA_override_visibility`, `enable_<smart album>`, `recent_age`,
  `photo_layout`, sorting defaults (`sorting_albums_col/order`, `sorting_photos_col/order`), `timeline_*`, `shared_albums_visibility_default`, `login/registration` toggles.
* Admin UI groups them via `config_categories`; secret values hidden from API.

### 6.2 `config/features.php` (env-driven code feature flags, NOT in DB)
Read via `App\Assets\Features::active('name')` / `inactive()` / `allAreActive([...])`; throws if the key does not exist. Booleans from env at boot:
`force_https`, `log_404_errors`, `legacy_v4_redirect`, `legacy_v3_db_prefix`, `log-viewer`, `use-s3` (needs AWS key + `S3_ENABLED`), `disable-basic-auth`, `disable-webauthn`, `hide-lychee-SE`, `latency`,
`v8`, `nuxt_ui`, `struct-of-array` (front-end generations/endpoints), `require-content-type`, `vite-http-proxy`, `disable-import-from-server`, `webshop` (default true), `webhook` (default false),
`webhook_timeout_seconds`, `location_decoding_requests_per_second`, `vulnerability-check`, `update-check`, `populate-request-macros`, `ai-vision` (default true; also needs DB config `ai_vision_enabled`),
`white_label_enabled`, `loading_indicator_url`, `use_fopen_for_url_imports`, `use-system-temp-dir`, `enable-caching` (also needs DB `cache_enabled`), `client-cache`.
Pattern: deployment-level kill switch (env) AND runtime switch (configs row) for optional modules.

### 7.4 Design notes / traps for the port
1. IDs: 24-char random strings for albums/photos (url-safe), integer ids for users/tags/permissions. Keep string ids to preserve URL shapes.
2. Tree: nested set gives cheap subtree queries (counts, recursive photos, browsability path check) but expensive writes. For a smaller port, either keep `_lft/_rgt` + `parent_id`, or use `parent_id` + recursive CTE
   (SQLite/Postgres/MySQL 8 all support them); the browsability check (every ancestor must be openable) and `is_recursive_nsfw` are the only places the tree matters for authorization.
3. Permissions are NOT inherited by SQL: each album needs its own `access_permissions` row (Lychee copies/derives them at creation via `default_album_protection = inherit`). The listing predicates in 4.3 are the contract to replicate.
4. A photo's visibility = visibility of any containing album (or ownership); photos with no album are private to owner/admin (unsorted).
5. Size variants: store relative `short_path` + `storage_disk`; compute URL at read time; the placeholder is a base64 webp inline in `short_path` (could be a column or a file in a port).
   Keep the `{type}/{xx}/{yy}/{rest}.{ext}` fan-out layout (avoids huge directories) and share one random stem across variants.
6. Denormalised album fields (`num_photos`, `num_children`, `min/max_taken_at`, auto covers) exist only for performance; a port can compute them on demand at first and cache later.
7. Dedup uses `original_checksum` (sha1) on upload; keep an index on it.
8. Dates: store `taken_at` in UTC plus the original IANA/offset tz string; show in original tz.
